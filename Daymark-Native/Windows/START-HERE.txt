DAYMARK NATIVE WINDOWS PREVIEW

Extract the complete ZIP, then double-click Daymark.exe.
Keep all of the supplied DLLs and other files beside the EXE.
No browser, Node.js, pnpm, or separate .NET installation is required.
Windows 10/11 x64 only. This preview is unsigned.

Your native calendar is stored separately from the web app:
%LOCALAPPDATA%\DaymarkNative\calendar.json
The previous save is calendar.json.bak. Use File > Save backup for a separate copy.
The first version-3 save preserves an older source file in calendar.json.v1.bak
or calendar.json.v2.bak. Older previews cannot read version-3 calendars.

This preview supports timezone-aware events, month/week/day
views, calendars with colors/visibility, recurring events and exceptions, search,
undo/redo, Horizon branding, Theme studio and backup/restore. Google/Microsoft
manual read-only sync requires your OAuth setup (see docs/ACCOUNT_SETUP.md).
Two-way provider editing and importing web calendar data are not implemented.

Use Ctrl+Shift+N for Quick Add. Try "Lunch tomorrow at noon for 45m", then
review the draft in the event editor. Set local event reminders in that editor.
Reminders > Keep running after closing keeps Daymark in the notification area.
Use File > Exit or the tray's Quit Daymark action to stop it.

Open Agenda for two weeks of events and due tasks. Ctrl+Shift+T opens Tasks.
Use Schedule time to reserve a linked block. Use Calendar sets to save groups
of visible calendars. Drag a timed event in Day or Week to reschedule it.
Select an event in the Schedule list and press Ctrl+M for keyboard rescheduling.
Calendars with tasks use version 5 and require Daymark v0.13 or later.

Use File > Import from another app to scan Fantastical, classic Outlook and
Thunderbird identities and local .ics files. Review items before importing.
Compatible appearance and default event-duration settings are optional.
Use File > Calendar accounts to sign back into imported Google/Microsoft
profiles. iCloud/CalDAV profiles are saved pending support. See docs/IMPORT.md
for export requirements, supported recurrence rules and migration limits.

For isolated testing, use the Open Test Calendar shortcut when provided, or run:
Daymark.exe --test-calendar
This keeps test events/preferences separate from your personal calendar.

This package is unsigned. Read docs/CODE_SIGNING.md and docs/PRIVACY.md.
SignPath acceptance and signing integration are pending.
See README.md and the QA records for verification results and limitations.

To remove this portable preview, close it and remove its extracted folder.
Your personal calendar remains at the data location above. Back it up before
removing it separately. TestCalendar data, if present, lives in the app folder.
